Как извлекать данные с сайтов на Python

0. Карта процесса: что именно делает сборщик

Скрейпинг (web scraping) — это автоматизированное получение данных с веб-ресурсов. Типичная программа состоит из отдельных этапов. Не смешивайте их в одну длинную функцию: тогда непонятно, где возникла ошибка.

  1. Постановка задачи. Определите конкретный набор полей: например, IPA-символ, название звука, пример слова, URL аудио.
  2. Разведка. Посмотрите страницу в браузере: HTML, DOM, запросы Network, источники медиа, правила сайта.
  3. Получение. Скачайте HTML или JSON через HTTP-клиент; при необходимости используйте настоящий браузер.
  4. Разбор. Извлеките нужные поля через CSS-селекторы, XPath, JSON-пути или анализ атрибутов.
  5. Нормализация. Приведите ссылки к абсолютным URL, удалите дубликаты, проверьте типы и пропуски.
  6. Загрузка ресурсов. Сохраните аудио и изображения, не перепутав HTML-страницу ошибки с бинарным файлом.
  7. Экспорт и проверка. Запишите JSON/CSV/TSV/БД, составьте отчёт и проверьте результат вручную.
Главный принцип: сначала выясните, откуда браузер получает нужные данные. Самый надёжный путь часто не «распарсить весь сайт», а найти JSON API или прямую публичную ссылку на ресурс и аккуратно использовать её.

Сборщик не угадывает содержимое страницы. Он получает конкретный HTTP-ответ или состояние браузера и затем извлекает из него данные.

1. Разведка сайта до написания кода

Самая важная привычка — не начинать сразу с Python. Сначала откройте страницу в браузере и выясните, где реально лежат интересующие данные.

1.1. View Source и Elements — не одно и то же

  • View page source / Просмотр кода страницы показывает исходный HTML, который сервер прислал первоначально.
  • Elements / Элементы показывает текущий DOM после выполнения JavaScript, кликов, подгрузки данных и изменений страницы.
  • Если в Elements звук присутствует, а в исходном HTML его нет, значит данные могли быть добавлены JavaScript-кодом.

1.2. Инструменты разработчика

  1. Откройте страницу и нажмите F12 или Ctrl+Shift+I.
  2. Перейдите во вкладку Network и включите Preserve log, чтобы не терять запросы при переходах и редиректах.
  3. Очистите журнал, перезагрузите страницу.
  4. Отфильтруйте запросы по Media, Fetch/XHR, затем при необходимости по Img.
  5. Нажмите кнопку звука на странице и посмотрите, какой новый запрос появился. Откройте его: изучите Request URL, Status, Headers, Response и Initiator.
  6. Нажмите правой кнопкой по запросу → Copy → Copy URL или Copy as cURL. Не публикуйте скопированные запросы, если там присутствуют cookies или токены.
Важно: запрос с типом media не обязательно содержит весь файл. Сайт может использовать поток, несколько фрагментов, blob URL или внутренний API. Смотрите на Content-Type, Response и Initiator.

1.3. Какие признаки искать

Практика 1. Откройте целевую страницу транскрипции. Найдите хотя бы одну кнопку воспроизведения. Запишите: HTML-элемент кнопки, где хранится символ, какой запрос выполняется при клике, какой Content-Type у ответа. Не начинайте массовую загрузку, пока не поняли эту связь.

2. Статическая страница: requests + BeautifulSoup

Если нужная информация присутствует в исходном HTML, используйте обычные HTTP-запросы. Это быстрее и легче браузерной автоматизации.

2.1. Установка

python -m venv .venv

# Windows PowerShell
.venv\Scripts\Activate.ps1

# macOS / Linux
source .venv/bin/activate

python -m pip install requests beautifulsoup4 lxml

2.2. Первая загрузка HTML

import requests
from bs4 import BeautifulSoup

url = "https://example.com/page"
headers = {
    "User-Agent": "Mozilla/5.0 (compatible; PersonalStudyBot/1.0)"
}

response = requests.get(url, headers=headers, timeout=(8, 20))
response.raise_for_status()  # остановиться на HTTP 4xx/5xx

print("Финальный URL:", response.url)
print("Код ответа:", response.status_code)
print("Тип содержимого:", response.headers.get("Content-Type"))

soup = BeautifulSoup(response.content, "html.parser")
print(soup.title.get_text(strip=True) if soup.title else "Без title")

requests получает ответ сервера. BeautifulSoup ничего не загружает из интернета: он только разбирает уже полученный HTML/XML. Такое разделение полезно для отладки.

2.3. Почему используется response.content

response.content возвращает байты, а BeautifulSoup пытается определить кодировку по самому документу. response.text уже является строкой, декодированной Requests. Оба подхода работают часто, но при проблемах с кодировкой важно сравнить объявленную кодировку, заголовки ответа и результат декодирования.

2.4. Сессия

import requests

session = requests.Session()
session.headers.update({
    "User-Agent": "Mozilla/5.0 (compatible; PersonalStudyBot/1.0)",
    "Accept-Language": "en-US,en;q=0.9",
})

page = session.get("https://example.com", timeout=20)
page.raise_for_status()

# Повторные запросы в той же Session переиспользуют соединения
# и автоматически сохраняют cookies, присланные сервером.
other = session.get("https://example.com/next", timeout=20)
other.raise_for_status()
Проверка: если в браузере видно десять карточек, а в response.text их нет, проблема не в BeautifulSoup. Значит, нужен другой endpoint или браузер, исполняющий JavaScript.

3. Как извлекать нужные элементы из HTML

Не выбирайте элементы «по номеру», например третий div на странице. Ищите стабильные признаки: id, класс, семантические теги, data-атрибуты, aria-label или связь с известным текстом.

3.1. CSS-селекторы

СелекторЗначение
#playerЭлемент с id="player".
.sound-cardВсе элементы с классом sound-card.
audio sourceВложенный source внутри audio.
[data-audio]Элементы с атрибутом data-audio.
button[aria-label]Кнопки с атрибутом доступного названия.
from bs4 import BeautifulSoup

html = """<div class='sound-card'>
  <span class='ipa'>/θ/</span>
  <span class='example'>think</span>
  <audio controls><source src='/audio/think.mp3' type='audio/mpeg'></audio>
</div>"""

soup = BeautifulSoup(html, "html.parser")

for card in soup.select(".sound-card"):
    symbol = card.select_one(".ipa")
    example = card.select_one(".example")
    source = card.select_one("audio source")

    record = {
        "symbol": symbol.get_text(strip=True) if symbol else None,
        "example": example.get_text(strip=True) if example else None,
        "audio": source.get("src") if source else None,
    }
    print(record)

3.2. Относительные ссылки

Из HTML можно получить адрес вроде /media/phonemes/th.mp3. Это не полный URL. Преобразуйте его через urllib.parse.urljoin, используя адрес страницы, на которой нашли ссылку.

from urllib.parse import urljoin

page_url = "https://example.com/pronunciation/english"
relative = "../media/th.mp3"
absolute = urljoin(page_url, relative)
print(absolute)
# https://example.com/media/th.mp3

3.3. Атрибуты, а не только теги

Источник аудио может храниться не в src, а в data-src, data-audio, data-file, onclick или внутри JSON в script. Исследуйте DOM: универсального имени атрибута не существует.

for element in soup.select("[data-audio], [data-src], audio, source"):
    print(element.name, element.attrs)

# Inline JavaScript тоже иногда содержит адрес ресурса:
for script in soup.find_all("script"):
    script_text = script.string or script.get_text()
    if ".mp3" in script_text or ".ogg" in script_text:
        print(script_text[:1000])
Не полагайтесь на один CSS-селектор. Дизайн сайта может измениться. Лучше выделить отдельную функцию parse_card() и проверять, что извлечённые значения имеют ожидаемый формат.

4. Аудио, изображения и другие файлы

Загрузить HTML и сохранить MP3 — две разные операции. Медиафайл является бинарным содержимым HTTP-ответа; не записывайте его через response.text.

4.1. Найти известные типы источников

from bs4 import BeautifulSoup
from urllib.parse import urljoin

soup = BeautifulSoup(html, "html.parser")

media_urls = []
for tag in soup.select("audio[src], audio source[src], video[src], img[src]"):
    media_urls.append(urljoin(page_url, tag["src"]))

# Не забудьте варианты с data-src и srcset.
for tag in soup.select("img[data-src], source[srcset]"):
    if tag.has_attr("data-src"):
        media_urls.append(urljoin(page_url, tag["data-src"]))
    if tag.has_attr("srcset"):
        # srcset содержит несколько кандидатов с указанием ширины/density.
        print("srcset:", tag["srcset"])

4.2. Безопасное сохранение бинарного файла

from pathlib import Path
from urllib.parse import urlparse
import requests

url = "https://example.com/media/phoneme.mp3"
out = Path("downloads/phoneme.mp3")
out.parent.mkdir(parents=True, exist_ok=True)

with requests.get(url, stream=True, timeout=(10, 30)) as response:
    response.raise_for_status()
    content_type = response.headers.get("Content-Type", "")
    if "text/html" in content_type.lower():
        raise ValueError("Сервер вернул HTML, а не аудио")

    total = 0
    with out.open("wb") as file:
        for chunk in response.iter_content(128 * 1024):
            if not chunk:
                continue
            total += len(chunk)
            if total > 30 * 1024 * 1024:
                raise ValueError("Файл превысил допустимый размер")
            file.write(chunk)

print("Сохранено:", out, "байт:", out.stat().st_size)

4.3. Почему расширение файла не гарантирует формат

URL может не иметь расширения, а сервер способен вернуть HTML-страницу с HTTP 200. Проверяйте HTTP-статус, Content-Type и сигнатуру файла. Например, MP3 часто начинается с ID3 или MPEG frame sync; WAV — с RIFF/WAVE; Ogg — с OggS. Для массового импорта полезно вести отчёт: URL, MIME-тип, размер, результат проверки.

4.4. Символы транскрипции

Большинство IPA-символов — это символы Unicode, а не отдельные изображения. Их лучше хранить как текст в UTF-8: например θ, ð, ʃ, ŋ. Отдельный SVG/PNG нужен только если на исходном сайте символ представлен рисунком или специальным спрайтом. В таком случае сначала проверьте Elements: может быть это SVG, CSS-псевдоэлемент либо web-font.

Практика 2. Скачайте один MP3-файл и проверьте его: размер больше нуля, браузер его открывает, начало файла не содержит HTML. Только после этого масштабируйте загрузку на весь список.

5. Редиректы, сессии, cookies и HTTP-заголовки

Перенаправление — обычный ответ HTTP, который сообщает клиенту, куда отправить следующий запрос. Несколько последовательных редиректов — это цепочка, а не ошибка сама по себе.

КодОбщее назначениеПрактический смысл
301Постоянное перенаправлениеРесурс перемещён; клиент получает новый адрес.
302Временное перенаправлениеЧасто используется после старого URL или входа.
303Переход к другому ресурсу через GETЧасто встречается после отправки формы.
307/308Перенаправление с сохранением методаКлиент не должен произвольно превращать POST в GET.

5.1. Посмотреть цепочку Requests

response = session.get(url, allow_redirects=True, timeout=20)
response.raise_for_status()

for hop in response.history:
    print(hop.status_code, hop.url, "→", hop.headers.get("Location"))

print("Финальный адрес:", response.url)
print("Финальный статус:", response.status_code)

5.2. Зачем нужны заголовки

  • User-Agent идентифицирует HTTP-клиент. Указывайте честный, понятный идентификатор; не выдавайте себя за браузер для обхода запретов.
  • Referer сообщает страницу, с которой пришёл запрос. Некоторые сайты проверяют его при отдаче медиафайлов.
  • Accept / Accept-Language описывают желаемые типы ответа и язык.
  • Cookie хранит состояние сессии. Используйте requests.Session(), а не копируйте cookies в публичный код.
  • Authorization может содержать секретный токен. Не публикуйте его и не помещайте в репозиторий.

5.3. Сессия и куки

import requests

session = requests.Session()
response = session.get("https://example.com/start", timeout=20)
response.raise_for_status()

# Сервер может установить cookies; Session хранит их сам.
print(session.cookies.get_dict())

next_response = session.get("https://example.com/account", timeout=20)
next_response.raise_for_status()
Граница автоматизации: не используйте код для обхода платной подписки, CAPTCHA, блокировок доступа, аутентификации, ограничений частоты или технических средств защиты. Если ресурс требует входа, работайте только с собственным аккаунтом, разрешённым способом и в рамках условий сервиса.

6. Динамические сайты: Playwright

Если содержимое появляется после выполнения JavaScript, обычный запрос может вернуть «пустой каркас». Тогда используйте настоящий браузер — например, Playwright. Он исполняет JavaScript, ждёт элементы, кликает, прокручивает страницу и позволяет получить итоговый DOM.

6.1. Установка Playwright

python -m pip install playwright
python -m playwright install chromium

6.2. Получить страницу после выполнения JavaScript

import asyncio
from playwright.async_api import async_playwright
from bs4 import BeautifulSoup

async def main():
    async with async_playwright() as p:
        browser = await p.chromium.launch(headless=True)
        page = await browser.new_page()

        response = await page.goto(
            "https://example.com/dynamic",
            wait_until="domcontentloaded",
            timeout=45000,
        )
        print("HTTP:", response.status if response else None)
        print("После редиректов:", page.url)

        # Предпочтительнее ждать конкретный элемент, чем спать фиксированное время.
        await page.locator(".sound-card").first.wait_for(timeout=15000)
        html = await page.content()
        soup = BeautifulSoup(html, "html.parser")
        print("Карточек:", len(soup.select(".sound-card")))

        await browser.close()

asyncio.run(main())

6.3. Типы ожидания

РежимКогда применятьОграничения

networkidleПолезно для некоторых страниц, когда сеть затихает.Сайты с аналитикой, WebSocket или polling могут не достичь idle.

6.4. Нажать кнопку и получить новое состояние

button = page.get_by_role("button", name="Play sound")
await button.click()

# Ждём изменения страницы или появления audio.
await page.locator("audio source").wait_for(timeout=8000)
source = await page.locator("audio source").get_attribute("src")
print("Audio source:", source)

Если точный текст кнопки неизвестен, изучите HTML и используйте подходящий CSS-локатор. Не кликайте все элементы подряд: часть кнопок может отправлять формы, менять настройки, начинать загрузку или переходить на другую страницу.

6.5. Перехват сетевых ответов

async def main():
    async with async_playwright() as p:
        browser = await p.chromium.launch()
        page = await browser.new_page()

        async def log_response(response):
            headers = await response.all_headers()
            content_type = headers.get("content-type", "")
            if content_type.startswith("audio/") or ".mp3" in response.url:
                print(response.status, content_type, response.url)

        page.on("response", log_response)
        await page.goto("https://example.com", wait_until="domcontentloaded")
        await page.get_by_role("button", name="Play sound").click()
        await page.wait_for_timeout(1200)
        await browser.close()

Playwright различает события запроса, ответа и завершения запроса. У перенаправления появляется новый запрос; его можно связать с предыдущим через redirected_from. HTTP-ответ 404 всё равно является завершившимся HTTP-обменом — проверяйте статус отдельно.

Когда браузер не нужен: если Network показывает публичный JSON endpoint, часто проще запросить его напрямую. Playwright нужен для выполнения сценария браузера, а не как замена любому HTTP-запросу.

7. Найти API, через которое сайт получает данные

Многие страницы получают карточки, списки, профили и аудиоссылки из JSON API. Браузер посылает запрос, сервер возвращает JSON, JavaScript строит интерфейс. Часто это проще парсинга DOM.

7.1. Алгоритм поиска

  1. Откройте Network → Fetch/XHR.
  2. Перезагрузите страницу и найдите запросы с JSON в Response.
  3. Посмотрите URL, метод, Query String Parameters, Request Payload и заголовки.
  4. Повторите действие на странице (поиск, следующая страница, выбор звука) и сравните запросы.
  5. Проверьте, можно ли получить тот же публичный ответ через Requests без обхода авторизации или защиты.

7.2. Запрос JSON

import requests

api_url = "https://example.com/api/sounds"
response = requests.get(api_url, timeout=20)
response.raise_for_status()
data = response.json()

# Сначала изучите структуру объекта:
print(type(data))
print(data.keys() if isinstance(data, dict) else len(data))

# Затем извлекайте конкретные поля, проверяя их наличие.
for item in data.get("items", []):
    print(item.get("symbol"), item.get("audioUrl"))

7.3. Почему API лучше HTML

  • Структурированные поля уже отделены друг от друга.
  • Меньше зависимости от дизайна и CSS-классов.
  • Обычно меньше объём ответа.
  • Проще пагинация, сортировка и проверка типов.

Но endpoint может быть внутренним, недокументированным или защищённым. Не считайте обнаружение URL разрешением на массовый сбор. Учитывайте условия сайта и ограничения использования API.

8. Пагинация, бесконечная прокрутка и несколько страниц

Данные редко ограничиваются одной страницей. Сайт может использовать обычные адреса ?page=2, кнопки «Далее», API-параметры offset/limit или cursor pagination.

8.1. Обычная пагинация

from urllib.parse import urljoin
from bs4 import BeautifulSoup
import requests

session = requests.Session()
base = "https://example.com/catalog"
page_url = base
seen = set()

for page_number in range(1, 51):  # жёсткий лимит
    response = session.get(page_url, timeout=20)
    response.raise_for_status()
    soup = BeautifulSoup(response.content, "html.parser")

    for card in soup.select(".item-card"):
        item_id = card.get("data-id")
        if item_id and item_id not in seen:
            seen.add(item_id)
            print(item_id)

    next_link = soup.select_one("a.next[href]")
    if not next_link:
        break
    next_url = urljoin(response.url, next_link["href"])
    if next_url == page_url:
        break
    page_url = next_url

8.2. API с offset/limit

offset = 0
limit = 50
all_items = []

while offset < 5000:
    response = session.get(
        "https://example.com/api/items",
        params={"offset": offset, "limit": limit},
        timeout=20,
    )
    response.raise_for_status()
    batch = response.json().get("items", [])
    if not batch:
        break
    all_items.extend(batch)
    offset += len(batch)

8.3. Infinite scroll

Сначала изучите Network: часто прокрутка вызывает API, а не загружает данные из HTML. Если без браузера нельзя, прокручивайте небольшими порциями, ждите появления новых элементов и проверяйте, увеличилось ли количество карточек.

previous = 0
for _ in range(20):
    await page.evaluate("window.scrollTo(0, document.body.scrollHeight)")
    await page.wait_for_timeout(900)
    current = await page.locator(".item-card").count()
    if current == previous:
        break
    previous = current
Обязательные ограничители: максимальное число страниц, максимальное число элементов, дедупликация, таймаут, пауза между запросами и условие остановки. Бесконечный цикл в сборщике — это не мелкая ошибка: он может перегрузить сайт и ваш компьютер.

9. Как сделать загрузчик устойчивым

Одноразовый скрипт может работать случайно. Надёжная программа должна переживать сетевые ошибки, временные блокировки, частично повреждённые данные и повторный запуск.

9.1. Retry и backoff

from requests import Session
from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry

retry = Retry(
    total=4,
    connect=4,
    read=2,
    status=3,
    backoff_factor=1.5,
    status_forcelist=[429, 500, 502, 503, 504],
    allowed_methods=["GET", "HEAD"],
    respect_retry_after_header=True,
)

session = Session()
adapter = HTTPAdapter(max_retries=retry)
session.mount("https://", adapter)
session.mount("http://", adapter)

9.2. Дедупликация

Один ресурс может встретиться как абсолютный и относительный URL, с разными fragment-частями или в нескольких карточках. Нормализуйте адреса, но не удаляйте query-параметры без понимания: иногда это токен или идентификатор файла.

9.3. Контроль целостности

  • Не сохраняйте файл, если ответ — HTML или JSON-ошибка.
  • Проверяйте размер и расширение по MIME/сигнатуре.
  • Считайте SHA-256, если важна идентичность файлов и повторная загрузка.
  • Сохраняйте промежуточный manifest: исходный URL, финальный URL, имя файла, тип, размер и связанный IPA-символ.
  • Ошибки отдельных элементов записывайте в журнал, не прекращая всю задачу.

9.4. Лимиты и задержки

import time

MAX_ITEMS = 100
DELAY_SECONDS = 1.0

for index, item in enumerate(items):
    if index >= MAX_ITEMS:
        break
    process(item)
    time.sleep(DELAY_SECONDS)

9.5. Кеширование

Сохраняйте уже обработанные URL в JSON/SQLite. При повторном запуске не загружайте повторно то, что успешно скачано и прошло проверку. Для больших проектов используйте SQLite: уникальный ключ по нормализованному URL или ID источника.

Разделите программу на небольшие уровни. Тогда смена сайта не заставит переписывать загрузчик, обработку ошибок и экспорт.

10.2. Как устроен созданный комплект IPA

Файл download_ipa.py использует этот принцип в компактном виде: сначала проверяет исходную страницу и редиректы, ищет аудио в HTML/атрибутах/скриптах, при необходимости запускает Playwright, скачивает обнаруженные публичные медиа, создаёт audio-map.js для локального сайта и формирует anki_import.tsv. Он не считает неизвестный HTML аудиофайлом и сохраняет отчёт о том, что удалось сопоставить.

11. Доступ, ограничения и безопасное обращение с данными

  • Сначала ищите официальный API, открытые данные или кнопку экспорта.
  • Проверьте Terms of Service, лицензию, robots.txt и правила использования медиа. robots.txt — техническая подсказка о предпочтениях обхода, а не универсальная лицензия на сбор и не замена правовой оценке.
  • Ограничивайте скорость запросов. Не отправляйте десятки параллельных запросов к небольшому сайту без необходимости.
  • Не обходите paywall, CAPTCHA, аутентификацию, антибот-защиту или ограничения API.
  • Не собирайте персональные или чувствительные данные без законного основания и необходимости.
  • Не публикуйте cookies, access tokens, session IDs, личные данные и приватные URL с временными токенами.
  • Не загружайте и не распространяйте чужие аудио/изображения публично без разрешения или подходящей лицензии. Для личного использования всё равно проверяйте условия источника и применимое право.
Уважайте отказ сервера. Если сервер возвращает 403/429, просит войти или прямо блокирует автоматизированный доступ, не пытайтесь маскировать или обходить ограничения. Уменьшите частоту, найдите официальный канал доступа либо остановитесь.

12. Практикум: от простого к самостоятельному

Задание A — статическая страница.
Откройте учебный ресурс с открытым HTML. Скачайте страницу Requests, найдите 5 заголовков через BeautifulSoup и сохраните их в JSON. Убедитесь, что у каждого объекта есть обязательное поле.
Задание B — загрузка картинок.
Найдите все изображения на учебной странице. Преобразуйте относительные URL в абсолютные, скачайте в папку, проверьте Content-Type и исключите дубликаты.
Задание C — пагинация.
Соберите первые 3 страницы тестового каталога. Добавьте лимит страниц, задержку, уникальный ключ и лог количества элементов.
Задание D — динамическая страница.
Найдите элемент, который появляется после JavaScript. Сначала посмотрите Network. Если есть открытый JSON endpoint — запросите его; в противном случае откройте страницу Playwright и дождитесь конкретного локатора.
Задание E — аудиобиблиотека.
Соберите только разрешённые звуковые файлы с одного учебного ресурса. Сопоставьте каждый URL с символом/словом. Экспортируйте CSV/TSV, создайте локальную HTML-страницу и отчёт по отсутствующим файлам.
